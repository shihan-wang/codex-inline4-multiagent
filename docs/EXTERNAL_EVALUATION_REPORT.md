### C. 0–720° 独立机械与碰撞扫描

独立扫描器没有调用项目快照函数；它自行实现 1-3-4-2 四冲程相位、滑块曲柄、凸轮半速与阀升程，然后把快照施加到装配。扫描包含连续 0–720°、每 1° 一项，共 721 项，预注册白名单哈希未改变。

机械约束实际结果：

- 边界发火顺序 `[1,3,4,2]`；发火顺序错误 0，冲程错误 0。
- 最大曲柄连杆闭合残差 `5.68e-14 mm`；1/4、2/3 配对误差 0 mm。
- 凸轮半速最大误差 0；相邻 1° 最大阀升程归一化变化 0.01310。

机械子分 **5/5**。

碰撞宽相只使用 AABB；闭合主壳窄相使用 Trimesh 三角形最近点和有向最近面伪法线，开口缸套使用由导出三角形边界推得的解析径向间隙。实际结果很差但有效：721/721 角度存在至少一个非白名单碰撞，共 7,561 个“碰撞对×角度”样本，最大测得穿透 107.0 mm；四根连杆各在 268 个角度越过对应缸套解析半径，最大 21.4139 mm。碰撞子分 **0/8**。

## 根据证据作出的推断

以下不是直接测量值：

1. Intel Arc 的 8.4 ms p95 表明在本机硬件路径上有稳定的 120 Hz 帧调度余量；它不能外推到其他 GPU、浏览器或普通电脑的统一帧率。
2. 移动 Lighthouse 的分数波动与高 TBT 表明受 CPU 降速时首次载入成本不稳定；这不是现场移动设备数据。
3. 51% 重复顶点部分可能来自硬边、UV/法线分裂和导出表示，但按预注册规则仍是不合格的未焊接几何卫生指标。
4. 主缸体相交不表示运动学相位错误；它说明视觉外壳缺少与内部机构匹配的真实空腔几何。运动约束 5/5 与碰撞 0/8 可以同时成立。
5. 自动名称检查和可访问性树不能替代 NVDA 真人测试；匿名截图/任务表也不能替代真实盲评偏好和任务表现。

## 证据与复现

所有原始数据只写入 `artifacts/external-eval/`；最终 `manifest.json` 将保存每个文件的相对路径、字节数和 SHA-256。主要索引：

- `performance/lighthouse/`：每次 JSON、HTML、元数据、失败尝试。
- `performance/web-vitals/`：50 个交互、Web Vitals、scene-ready、环境和日志。
- `performance/webgl/`：Intel Arc / SwiftShader 分路径原始结果、截图和 heap snapshot。
- `performance/spector/`：三场景每次尝试、截图/捕获或真实失败日志。
- `accessibility/`：九状态 axe JSON/截图、键盘、焦点、对比度与回流证据。
- `geometry/`：语义 GLB、导出清单、Trimesh、Blender 与 C 类计分卡。
- `mechanics/`：721 步装配与碰撞原始结果。
