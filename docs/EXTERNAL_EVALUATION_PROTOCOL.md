# V3 独立外部测评预注册协议

协议版本：1.0  
预注册日期：2026-08-31（Asia/Shanghai）  
固定对象：`7e5ea916a115dcef1bf3ba467a31b78c6206c612`  
固定标签：`v3-model-final^{}` 必须等于上述提交  
执行分支：`external-evaluation`

## 1. 冻结与独立性

1. 本协议必须在产生任何外部测评分数之前提交。协议提交后不得因结果不理想改变权重、阈值、排除条件、碰撞白名单或取中方法；若发现协议错误，只能追加勘误并同时保留原规则与按原规则计算的结果。
2. 测评期间禁止修改 `src/`。评估器只能导入、运行或导出固定提交的模型。开始和结束均执行 `git diff v3-model-final -- src`，结果必须为空。
3. 原始证据只写 `artifacts/external-eval/`，不得覆盖 v1/v2/v3 证据。失败运行保留；重跑写入新编号目录。
4. Lighthouse、持续 WebGL、Spector 单帧捕获、拓扑检查、机械扫描和人员盲评属于不同证据类型，不得互相替代。
5. 没有真实评审者数据时，人类盲评标为“待完成”，不得模拟或代填；没有 NVDA 操作者实测时，NVDA 项同样标为“待完成”。任一项缺失时不发布 100 分外部总分，也不把已测子项线性放大。

## 2. 100 分固定量表

| 方向 | 分值 |
|---|---:|
| A. Lighthouse、Web Vitals 与 WebGL 性能 | 25 |
| B. axe-core 与 WCAG 2.2 AA | 20 |
| C. 语义几何、拓扑与独立机械扫描 | 35 |
| D. 真实人员盲评、任务与 SUS | 20 |
| **总计** | **100** |

完整外部总分仅在 A–D 全部完成后计算。最终等级预注册为：90–100 卓越；80–89 高质量；70–79 合格；60–69 有明显不足；低于 60 不合格。等级边界同样不得事后调整。

## 3. A 类：性能与运行路径（25 分）

### 3.1 Lighthouse 冷缓存

- 对当前生产构建分别运行桌面、移动各 5 次。
- 每次使用新的浏览器用户目录、空 HTTP 缓存和独立输出目录；本地生产服务器、构建文件和浏览器版本固定。
- 运行顺序固定为 `D1,M1,M2,D2,D3,M3,M4,D4,D5,M5`，避免所有移动或桌面集中在温度相同的时间段。
- 报告 5 次原始值、中位数、最小值和最大值。不得只保留最佳运行。
- Lighthouse 的 TBT 只按 TBT 报告，不得写成 INP。

固定计分：

- 桌面 Performance 中位数（3 分）：≥95 得 3；90–94 得 2.5；80–89 得 1.5；60–79 得 0.5；<60 得 0。
- 移动 Performance 中位数（4 分）：≥90 得 4；80–89 得 3；70–79 得 2；50–69 得 1；<50 得 0。
- 实验室 LCP（4 分）：桌面和移动各 2 分；该类中位数 ≤2.5 s 且最大值 ≤4.0 s 得满分，中位数 ≤4.0 s 得 1 分，否则 0。
- CLS（2 分）：桌面和移动各 1 分；中位数 ≤0.1 且最大值 ≤0.25 得 1，否则 0。

### 3.2 Web Vitals 与 scene-ready

- 使用独立页面注入脚本与 Event Timing/Web Vitals 记录，不从 Lighthouse TBT 推导交互指标。
- 每个桌面/移动配置使用新 profile 各运行 5 次，保存 LCP、CLS、事件条目和脚本化交互指标。
- 可报告脚本化 INP 或 event-to-next-paint，但必须标注“实验室脚本交互”，不得冒充真实用户第 75 百分位现场数据。
- `scene-ready` 是项目专用、非 Core Web Vital 指标：从 navigation start 到 Canvas 尺寸非零、WebGL2 上下文可取得、暂停按钮可操作、曲轴遥测连续两个动画帧发生变化、三种模式按钮已初始化的最晚时刻。

固定计分：

- scene-ready（4 分）：桌面中位数 ≤2.5 s 得 2、≤4.0 s 得 1；移动中位数 ≤4.0 s 得 2、≤6.0 s 得 1；否则 0。
- 实验室脚本交互延迟（3 分）：所有有效交互的 p75 ≤200 ms 得 3；≤300 ms 得 2；≤500 ms 得 1；否则 0。若浏览器无法产生 Event Timing，则标为未测，不得以 TBT 替代。

### 3.3 持续 WebGL 与 SwiftShader

- Intel Arc D3D11 与 SwiftShader Vulkan 分开执行、分开统计，各 3 次。
- 每次先暖机 5 秒，再采样至少 600 帧或 30 秒，以较晚完成者为准；记录平均 FPS、p50/p95/p99/max 帧时间、Draw Calls、堆快照、WebGL renderer、页面异常和应用控制台错误。
- 硬件路径（3 分）：三次均无应用错误/上下文丢失且合并 p95 ≤16.7 ms 得 3；≤33.3 ms 得 2；≤50 ms 得 1；否则 0。
- SwiftShader 兼容（2 分）：三次均无应用错误/上下文丢失且 p95 ≤150 ms 得 2；功能通过但 p95 >150 ms 得 1；功能失败得 0。软件与硬件不得混合平均。

## 4. B 类：axe-core 与 WCAG 2.2 AA（20 分）

### 4.1 自动扫描状态

axe-core 必须分别扫描：桌面实体、X-Ray、剖切、零件已选择、暂停、装配分解，以及 390×844 的初始、左抽屉打开、右抽屉打开，共 9 个状态。每个状态保存完整 JSON、截图和页面 URL/viewport。

- axe critical/serious（6 分）：0 critical 且 0 serious 得 6；0 critical 且 serious 规则种类 ≤2 得 4；0 critical 且 serious ≤5 得 2；存在 critical 或 serious >5 得 0。major/minor 全部报告但不额外扣分。
- 名称/角色/状态（3 分）：所有可操作控件都有可访问名称，模式、开关、抽屉与暂停状态可编程读取且同步，全部通过得 3；1 个孤立问题得 2；2–3 个得 1；更多或核心控制失败得 0。
- 对比度（2 分）：axe `color-contrast` 0 违规且人工抽查覆盖常规文本、焦点、活动模式、标签和抽屉得 2；仅非核心小字存在 ≤2 个实例得 1；否则 0。

### 4.2 人工但非盲评检查

- 键盘与焦点（3 分）：仅键盘完成暂停、模式、六机位、复位、三个开关、左右抽屉和零件检查器；无焦点陷阱、焦点不可见或顺序错误得 3；1 个轻微问题得 2；核心任务失败得 0。
- 缩放与回流（3 分）：200% 文本缩放与等效 400%/320 CSS px 回流下核心控制可达、无双向滚动要求、内容不丢失得 3；1 个非核心裁切得 2；需要双向滚动或核心功能丢失得 0。
- NVDA（3 分）：由真实 NVDA 操作者验证页面标题、运行状态、滑杆、模式、机位、开关、抽屉、零件检查器和动态状态；全部清楚得 3，1–2 个轻微朗读问题得 2，核心控制不可用得 0。没有真实操作者时必须标为待完成。

axe 零违规不等于 WCAG 2.2 AA 通过。报告必须把自动结果、键盘/焦点、缩放/回流、对比度、名称/角色/状态和 NVDA 分开。

## 5. C 类：几何、拓扑与机械（35 分）

### 5.1 只读语义 GLB 导出

- 评估器从固定源码实例化装配，但不得更改模型实现。
- GLB 节点保留唯一语义零件名和原始 `partId`，并在 extras/清单中分类为：`structural-solid`、`dynamic-mechanism`、`fluid-effect`、`label`、`auxiliary`。
- 结构实体和动态件进一步登记 `closureExpectation`：`closed`、`intentionally-open`、`not-applicable`。
- 只有设计上应为封闭实体的单件要求水密；整个发动机装配、开口管道、弹簧、教学流线、粒子、标签和辅助几何不得被要求组成单一 watertight 网格。

语义覆盖（5 分）：100% 可渲染三角形有分类、所有可拾取根有稳定语义名、GLB 与清单哈希匹配得 5；分类覆盖 ≥99% 得 4；≥95% 得 2；否则 0。

### 5.2 Blender 与 Trimesh 双工具检查

两者分别报告每个语义节点的：顶点/面数、连通分量、非流形边、边界边、重复顶点、重复面、退化三角形、法线/绕序、水密性。禁止只用一个工具的结论复制成另一个工具结果。

- 应闭合实体水密性（10 分）：两工具一致确认 100% 得 10；≥98% 得 8；≥95% 得 6；≥90% 得 3；<90% 得 0。按语义实体计数，同时报告按三角形加权比例。
- 网格卫生（5 分）：退化三角形为 0 得 2；重复面为 0 且未焊接重复顶点比例 ≤0.1% 得 1；法线/绕序错误为 0 得 2。任一工具发现问题即按较差结果计分。
- 跨工具一致性（2 分）：两工具对 closureExpectation=closed 节点的水密判断一致率 ≥98% 得 2；≥95% 得 1；否则 0。

### 5.3 独立 0–720° 扫描

- 扫描器独立实现四冲程相位、滑块曲柄、凸轮半速与阀升程，不调用项目的快照计算函数；可以调用装配更新接口应用独立快照。
- 0–720° 每 1° 一个样本，共 721 个；记录核心动态件的变换、约束残差、最小距离和碰撞对。
- 有意配合/接触只允许使用本协议同时提交的 `evaluation/config/collision-whitelist.json`；未预登记的碰撞不得事后加入白名单消除失败。

固定计分：

- 非白名单碰撞（8 分）：零碰撞得 8；仅存在最大穿透 ≤0.1 mm 且影响样本 ≤3 得 6；≤0.5 mm 且样本 ≤10 得 3；否则 0。AABB 仅用于宽相过滤，最终碰撞必须基于三角形/BVH或解析间隙。
- 机械约束（5 分）：曲柄连杆闭合误差 <0.01 mm（1）；1/4、2/3 配对误差 <0.01 mm（1）；发火顺序/冲程 721 样本零错误（1）；凸轮比 0.5 且阀事件无跳变（1）；凸轮—挺柱及活塞—缸盖最小间隙非负（1）。

## 6. D 类：真实人员盲评（20 分）

### 6.1 设计与最小样本

- 生成不包含版本名、提交号或制作顺序的 v2/v3 材料；使用固定种子 `20260831` 随机映射匿名代码并平衡先后顺序。
- 采用同一参与者比较两套材料。最低有效样本 n=8，建议 n≥12；尽量包含至少 4 名有机械背景和 4 名无机械背景参与者。
- Codex 只生成材料、记录表和统计脚本，不填写评审数据。

### 6.2 固定任务与计分

- 任务完成率（5 分）：V3 ≥90% 得 5；≥80% 得 4；≥70% 得 3；≥60% 得 2；否则 0。
- 完成时间（2 分）：V3 中位数 ≤V2 的 95% 得 2；≤110% 得 1；否则 0。
- 错误率（3 分）：≤5% 得 3；≤10% 得 2；≤20% 得 1；否则 0。
- 六项视觉评分（6 分）：结构识别、比例可信、材料辨识、内部可读、剖切表达、标签/教学性，各用 1–7 分；每项 V3 均值除以 7 后计 0–1 分，六项相加。不因 V3 未显著优于 V2 而篡改原始绝对分。
- SUS（4 分）：V3 SUS ≥85 得 4；≥80 得 3；≥68 得 2；≥50 得 1；<50 得 0。

固定任务为：识别曲轴到凸轮轴传动；判断四缸当前冲程与发火顺序；追踪进气到涡轮/气缸路径；找到润滑和冷却分支；在剖切中指出活塞—连杆—曲轴链；选择零件并读出材料/功能；在窄屏打开控制与工况抽屉后恢复轴测实体视图。

### 6.3 排除条件

只排除：未完成超过 1 个任务；自报页面/设备故障导致任务无法进行；事先知道匿名代码对应版本；记录缺失超过 20%；未同意匿名使用数据。不得因评分低、偏好 v2、用时长或机械知识不足排除。所有排除记录保留并给出原因。

## 7. 运行排除与重跑规则

自动运行仅可因浏览器崩溃、导航失败、Canvas 缺失、目标 renderer 与声明路径不符、测量脚本自身异常或操作系统强制中断而标为无效。性能差、审计失败、控制台错误和不理想分数都是有效结果，不得排除。无效运行保留原始证据，并使用递增编号追加重跑；报告同时列出有效和无效数量。

## 8. 证据格式

目录固定为：

```text
artifacts/external-eval/
  manifest.json
  environment/
  performance/lighthouse/{desktop,mobile}/run-01..05/
  performance/web-vitals/{desktop,mobile}/run-01..05/
  performance/webgl/{intel-arc,swiftshader}/run-01..03/
  performance/spector/{solid-isometric,section-crank,xray-valvetrain}/
  accessibility/axe/<state>/
  accessibility/manual/
  geometry/export/
  geometry/trimesh/
  geometry/blender/
  mechanics/
  blind-review/materials/
  blind-review/forms/
  blind-review/results/
  logs/
```

每个机器运行至少保存：UTC/本地时间、命令、退出码、Git HEAD、目标标签剥离值、操作系统、CPU/GPU/renderer、浏览器与工具版本、viewport、原始 JSON/HTML/截图、标准输出/错误摘要。最终 `manifest.json` 保存所有证据的相对路径、字节数和 SHA-256。GLB 同时保存导出清单与 SHA-256。

## 9. 最终报告规则

`docs/EXTERNAL_EVALUATION_REPORT.md` 必须分为：实际测量、人工盲评、根据资料/工具作出的推断、未测项目。报告展示每项原始值、按本协议计算的得分和失败；不得隐去失败运行。没有真实盲评或 NVDA 数据时明确写“待完成”，且不得给出外部 100 分总分。
