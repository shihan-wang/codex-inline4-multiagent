# V4 第一阶段：视觉与性能回归基线审查

审查代理：`v4_visual_perf_baseline`。审查性质：独立、只读。固定模型提交：`7e5ea916a115dcef1bf3ba467a31b78c6206c612`；审查时分支 HEAD：`eccde839811d6991b9583f3c4fd6c08918ec64c1`。`src/` 相对 V3 和工作树均无差异，本代理没有改动模型源码。

## 结论

V3 在 Intel Arc 硬件路径上有稳定的 120 FPS/8.4 ms p95 基线，三种观察模式、六个机位、分解、标签、流体、暂停、自由相机和零件检查均在真实生产页面复验通过；应用控制台异常、页面异常和 WebGL context loss 均为 0。视觉上，配色层级、金属/壳体/流体区分和剖切/X-Ray 的机械教学可读性已经形成强基线。

确认的最明显视觉问题是：实体轴测开启分解后，上移的气门室罩/顶部附件越过画面上缘，无法在 1280×720 一屏看完整，削弱了“分解即解释装配关系”的效果。性能方面，移动冷缓存 LCP 和 SwiftShader 帧率是实测限制，但后者属于软件兼容路径，不能通过牺牲硬件画质来刷分。

## 方法与证据边界

- 没有重跑昂贵的 Lighthouse 5+5、Intel Arc/SwiftShader 各 3 次持续 WebGL 或 Spector；逐项核验了其原始结果、次数、renderer 与成功捕获。
- 新增一次低成本硬件浏览器验收，覆盖 1280×720、390×844、三模式、六机位、三个开关、分解、标签、流体、零件选择及相机操作。
- 新增 9 张确定性 V3 截图：评估层把 rAF 时间戳固定为 60 Hz 并在第 361 帧停止，画面均为暂停且遥测显示 `000.0°`。这是只读评估注入，不是产品实现。
- Spector 单帧 GPU 命令与 30 秒持续帧时间保持分开；Intel Arc 与 SwiftShader 保持分开。
- Lighthouse TBT 只称为 TBT；实验室脚本交互不冒充现场 INP p75。
- 以下视觉判断是代理专家审查，不是真人盲评，也不替代 NVDA。

代表画面：`representative-montage.png`。全部定量值和冻结阈值见 `baseline-manifest.json`。

## 缺陷与建议

### VP-01 — P2：分解视图没有随装配包围盒重新构图

- **实际证据**：`fixed-v3/solid-isometric-exploded-1280x720.png` 中，上移后的黑色气门室罩和顶部共轨区域被画面上缘切断；相同机位未分解的 `solid-isometric-1280x720.png` 完整可见。
- **用户影响**：用户打开“装配分解”后反而不能同时看清全部分层，顶部部件与缸盖的空间关系缺少完整上下文。
- **预计收益**：高；一处构图修复可直接提升功能可信度和教学性。
- **实现成本**：低到中；可在分解状态对轴测相机采用经过验证的后移/目标偏移，或做限定包围盒 fit。
- **引入风险**：中；全局相机参数可能破坏六个机位，包围盒若包含标签/流体会过度缩远。
- **可验证验收**：同一 `1280×720 / 000.0° / solid / isometric / exploded` 截图中，结构实体的最高/最低点均落在左右面板之间的可视安全区，且未分解轴测、曲柄剖切、配气 X-Ray 构图不退化。
- **建议**：进入 V4 候选清单。

### VP-02 — P2：移动冷缓存首屏性能波动且 LCP 超过 2.5 s

- **实际证据**：移动 Lighthouse LCP 中位 3458 ms、范围 3062.3–5968.5 ms；Performance 42–88，离散明显。桌面中位仅 631.5 ms，差异主要在移动节流条件。
- **用户影响**：较慢设备/冷启动时首屏可能等待 3–6 秒；并非场景可交互时间本身（移动 scene-ready 中位 382.8 ms）。
- **预计收益**：中到高；改善慢设备首次感知。
- **实现成本**：中到高；需要拆分首屏视觉、检查 LCP 候选与主线程长任务，不能靠降低发动机几何质量。
- **引入风险**：中高；延迟场景或字体/界面资源可能造成视觉闪烁、指标转移，单次 Lighthouse 容易误判。
- **可验证验收**：只有涉及启动路径时，按相同协议重新跑移动冷缓存 5 次；以中位数和范围判断，不能用单次最好值。目标优先降到中位 ≤2500 ms；至少不得比 V3 中位 3458 ms/最大 5968.5 ms 更差。
- **建议**：若 V4 实施触碰启动路径则处理；若仅做几何/无障碍，应记录为未实施的独立性能债，不扩大本轮耦合面。

### VP-03 — P2：SwiftShader 能运行但不可流畅交互

- **实际证据**：三次仅 1.854–2.557 FPS，p95 700.1–916.7 ms；应用错误和 context loss 为 0。Intel Arc 则稳定约 120 FPS。
- **用户影响**：强制软件渲染环境下只能视为功能兼容，不能当实时教学体验。
- **预计收益**：如果能改善则高，但受软件 rasterizer 与约 267 draw/frame 双重限制。
- **实现成本**：高；需要专门低质量路径、合批/LOD 或禁用效果。
- **引入风险**：高；自动降质可能误伤硬件路径、降低 V3 主要视觉效果，且本轮只有一次 SwiftShader 复验预算。
- **可验证验收**：renderer 必须明确为 SwiftShader；单独报告，0 应用错误/0 context loss，不能与 Intel Arc 平均。若无独立低质量策略，至少保持 1.85 FPS、p95 ≤916.7 ms 的兼容性下限。
- **建议**：本轮明确不以牺牲硬件画质为代价实施。保留兼容性门槛，不宣称软件路径流畅。

### VP-04 — P3：静态姿态中流体开关差异较弱

- **实际证据**：相同 X-Ray 轴测、`000.0°` 的 flows-on/off 截图 SSIM 为 0.993911，说明像素差异真实存在但占画面比例小；动态正式验收确认开关状态有效。
- **用户影响**：静态截图或暂停讲解时，学生可能难以立即定位润滑/冷却/气流；运行状态下影响较小。
- **预计收益**：中低。
- **实现成本**：中；增强线宽/亮度/局部图例或暂停时保留示意流线。
- **引入风险**：中；过亮会遮挡核心机构并增加透明排序噪声。
- **可验证验收**：同状态 A/B 截图加人工识别任务，确认观察者能在不看开关的情况下辨别开/关；同时 X-Ray 内部零件边缘仍清楚。
- **建议**：低收益不实施，除非主代理合并其他教学可读性改动时能低风险顺带改善。

### VP-05 — P3/设计边界：曲柄和配气专用机位有意裁掉非目标系统

- **实际证据**：`section-crank` 中顶部凸轮局部贴近/越过上缘，`xray-combustion` 中下部曲轴局部出画；目标曲柄连杆或配气机构均占据主要可视区域且标签清楚。
- **用户影响**：缺少完整装配轮廓，但换来目标机构更大的教学尺度。
- **预计收益**：全机强行入画收益低，可能降低细节可读性。
- **实现成本**：低。
- **引入风险**：中；盲目缩远会使阀门、弹簧、连杆细节变小。
- **可验证验收**：专用机位目标机构无遮挡、标签不重叠、左右面板不遮目标；无需把非目标系统全部纳入画面。
- **建议**：确认为合理构图，不实施“全机入画”。这与 VP-01 的分解视图不同：分解功能的目标正是展示完整层级。

## 冻结的不退化门槛

- 硬件 Intel Arc：持续样本平均 FPS ≥110、p95 ≤10 ms、draw/frame ≤282，0 应用错误，0 context loss。
- SwiftShader：仅兼容性门槛；FPS ≥1.85、p95 ≤916.7 ms、0 应用错误/context loss，单独报告。
- 如果材质/管线/draw 结构明显变化才重跑 Spector；单帧 draw 上限按 V3 +5%：实体 282、剖切 281、X-Ray 279。
- 如果启动路径变化才重跑完整 Lighthouse/Web Vitals：桌面/移动 5+5，同协议；不得用单次替代中位数。
- 正式浏览器验收必须继续通过；三模式、六机位、三个开关、暂停、相机旋转/缩放/平移、五字段零件检查、桌面/窄屏抽屉全部有效。
- 固定同状态截图至少保留实体轴测、曲柄剖切、配气 X-Ray 和装配分解，以 V3 本目录文件为前图。

## 技术裁决建议

优先修 VP-01；VP-02 只有在本轮触及启动路径时进入实现，避免为了指标重构加载链；VP-03 记录为软件路径限制，不能以降低 Intel Arc 视觉质量换分；VP-04/VP-05 为低收益或合理设计边界，建议不实施。无证据支持重写渲染器、削减主要系统或全局缩远六个机位。

本审查可以放行进入“汇总并选择修复”的阶段，但它不是 V4 最终放行：完成实现后仍需由未参与实现的代理实际复验同状态画面和受影响性能门槛。
