## 值得保留的优点

1. **核心机构并非低成本方块拼装。** `cameras/camera-crank-1280x720.png` 中四组活塞—连杆—曲轴链条清楚；`cameras/camera-combustion-1280x720.png` 中凸轮、气门、弹簧、喷油器和燃烧室标注形成了有效教学视图。
2. **零件细节密度有层次。** 活塞裙、浅碗、三道环、活塞销/销孔，曲轴平衡重，气门弹簧、燃油轨与支管、进排气歧管及涡轮均有独立几何，而非只靠贴图。
3. **材质配色有明确系统语义。** 铸铁/铝合金/机加工钢/黑色附件/橡胶/进排气与流体颜色可以区分；飞轮和涡轮高光为画面提供了焦点。
4. **三种观察模式确实改变了结构可见性。** X-Ray 能显示内部运动链，剖切能直接露出四缸活塞和曲轴；实体模式保持了完整轮廓。
5. **六机位具有教学分工。** 曲柄连杆与配气/燃烧预设尤其有效，标签也会随预设收敛到相关部件，避免默认全量标注。
6. **桌面 UI 完整且无溢出。** 1280×720 下左右面板、底部机位栏和顶栏均在视口内，主要操作状态清晰。
7. **实际浏览器稳定。** 页面无控制台错误、无页面异常；暂停、滑杆、模式、相机、旋转、缩放、平移与拾取均通过自动化验证。

## 缺陷清单

### V3-VIS-01 — 窄屏双面板遮蔽几乎整个模型，且隐藏关键机位

- **严重度：P1**
- **实际证据：** `browser/narrow-390x844.png`；`browser/acceptance-report.json` 显示 390 px 视口内左/右面板各 184 px，合计占 368 px；`src/style.css:149-153` 仍并排保留两面板，并隐藏第 5 个以后的非末尾机位按钮。
- **用户可见影响：** 窄屏虽然没有 DOM 溢出，但中间 3D 模型几乎不可见，用户无法有效旋转、观察或对照面板；曲柄连杆等关键预设不可直接访问。
- **预期收益：高。** 改为抽屉、折叠面板或分层切换后，窄屏会从“形式上适配”变成真正可用。
- **实现成本：中。** 需要响应式面板状态、触摸目标和底栏滚动/分页。
- **风险：中。** 折叠状态可能与桌面状态同步不当，触摸手势可能与 OrbitControls 冲突。
- **可验证验收：** 在 390×844 下中央画布至少保留可辨识的主要发动机轮廓和约 50% 可用宽度；全部六机位可访问；面板可开关；无水平/垂直溢出；触摸旋转、缩放和面板滚动互不抢占。

### V3-VIS-02 — 流体开关在 X-Ray 中几乎没有可感知差异

- **严重度：P1**
- **实际证据：** `flows/flows-on-xray.png` 与 `flows/flows-off-xray.png` 同尺寸对比几乎一致；`src/scene/assembly.ts:618-665` 的油/冷却液/进气路径半径仅 2.7、3.8、2.2（装配按 `WORLD_SCALE` 缩放），粒子数 34/46/28，且处在透明外壳与复杂零件后方。
- **用户可见影响：** “润滑、冷却、进气”作为核心教学系统虽然可切换，但用户很难看出路径、方向和开关效果，交互反馈显得无效。
- **预期收益：高。** 提升线宽、发光、方向粒子、路径分层或短时强调，可显著增强教学价值。
- **实现成本：中。** 需调整路径几何、深度策略、动画节奏及图例。
- **风险：中。** 过亮会污染 X-Ray，关闭深度测试会制造错误空间关系，增加粒子还会扩大 draw calls。
- **可验证验收：** 在 1280×720 的 X-Ray 与剖切机位中，油/冷却液/进气至少三种路径可沿连续方向追踪；开/关截图有明显感知差异；颜色与图例一致；关闭后相关几何全部消失；draw calls 不高于优化前预算。

### V3-VIS-03 — 前端风扇、水泵与曲轴附件缺少连续传动关系

- **严重度：P2**
- **实际证据：** `cameras/camera-front-1280x720.png` 中风扇、水泵与单一曲轴皮带轮呈分离状态；`src/scene/assembly.ts:560-595` 只建立一个 pulley、独立 fanHub 和独立 waterPump，没有皮带或相应从动轮。
- **用户可见影响：** 前视时附件像悬浮的孤立零件，无法解释水泵/风扇怎样从曲轴获得动力，削弱柴油机装配可信度。
- **预期收益：高。** 增加至少两从动轮和连续皮带能以很小的几何范围补全一条明显机械关系。
- **实现成本：中。** 程序化皮带路径与轮轴对齐需要适度计算。
- **风险：低至中。** 主要风险是皮带穿插罩壳、旋转方向或速比表现错误。
- **可验证验收：** 前视能看到曲轴轮—水泵/风扇轮的连续闭合皮带；皮带不穿模、不悬空；若动画化，旋转方向与轮径比一致；在实体/X-Ray/剖切中均不制造突兀残片。

### V3-VIS-04 — 缸体与缸盖的大体块仍偏“圆角盒体”

- **严重度：P2**
- **实际证据：** `cameras/camera-side-1280x720.png` 的侧面仍以大面积平板和规则边界为主；`src/scene/assembly.ts:92` 用单个 510×268×214 roundedBox 构成缸体主体，`src/scene/assembly.ts:122` 用单个 roundedBox 构成缸盖，随后叠加规则加强筋和圆形堵盖。
- **用户可见影响：** 内部核心机构细节丰富，但外壳的铸造轮廓、曲面过渡、主轴承座/水套/螺栓台阶缺少结构变化，限制高质量整体观感。
- **预期收益：中高。** 增加局部铸造隆起、凹槽、法兰、螺栓座和不完全规则的轮廓，会让外形更像发动机铸件而非工业箱体。
- **实现成本：中至高。** 需要在不引入昂贵布尔运算的前提下重组程序化壳体。
- **风险：中。** 细节过多会增加 draw calls、穿插和剖切碎片；错误的“装饰细节”可能降低机械可信度。
- **可验证验收：** 侧视与等距视图中缸体/缸盖至少出现可解释的轴承座、侧壁凹凸、法兰与螺栓台阶；轮廓不再由单一矩形主导；新增几何不遮挡核心运动链且满足性能预算。

### V3-VIS-05 — 顶视预设裁切主要系统，构图不够像稳定的总览

- **严重度：P2**
- **实际证据：** `cameras/camera-top-1280x720.png` 中进气总管贴近/越出上缘，排气、涡轮和下行管贴近/越出下缘，风扇也只有部分进入画面；`src/scene/constants.ts:39-42` 顶视位置为 `(0.01,13.5,0.01)`，没有基于可见包围盒与左右面板占用区做适配。
- **用户可见影响：** 用户点击“顶部”后无法一眼看到进排气与缸体的完整布局，预设价值低于曲柄/配气机位。
- **预期收益：高（相对成本）。** 调整距离、target、up 与面板安全区即可明显改善。
- **实现成本：小。** 常量或相机 fit 逻辑调整。
- **风险：低。** 只需防止在其他宽高比下过度留白。
- **可验证验收：** 相机过渡稳定后，发动机可见包围盒在左右面板之间并留 8–10% 安全边距；进气、排气、涡轮和风扇不被裁切；发动机纵轴方向清楚；1280×720 与 1600×1000 均通过截图检查。

### V3-VIS-06 — 选中高亮是跨空域的大包围盒，检查器滚动提示弱

- **严重度：P2**
- **实际证据：** `selected/selection-1280x720.png` 中排气歧管选择后出现覆盖整套歧管范围的巨大青色轴对齐包围盒；`src/scene/assembly.ts:808-830` 会收集同 partId 的全部候选并合并成一个 `Box3Helper`。右侧检查器在 1280×720 中只显示到关键参数，当前运动状态处在不可见下方；`src/style.css:39` 隐藏面板滚动条。
- **用户可见影响：** 高亮框穿过大量空白并遮挡模型，像调试辅助而不像成品反馈；用户容易误以为信息只有四项，忽略实时状态。
- **预期收益：中高。** 改为实际网格描边/材质发光或每子组局部框，并提供可见的滚动/折叠提示，可明显提升精致度。
- **实现成本：小至中。** 局部框较小；真正轮廓描边需后处理或额外渲染。
- **风险：中。** 后处理可能增加成本并与透明/剖切冲突；多框可能造成噪声。
- **可验证验收：** 点击至少五类主要零件时，高亮贴合实际网格且不跨越大块空域；X-Ray/剖切中不透出错误轮廓；1280×720 可看到全部五类信息，或有明显滚动条/“更多”提示；键鼠悬停与点击状态区分清楚。

### V3-VIS-07 — 剖切面没有封口/剖面材质，产生空壳与碎片感

- **严重度：P2**
- **实际证据：** `browser/desktop-section.png` 中缸体、缸盖和附件被裁开后只留下开放暗边，没有剖面封口或剖面纹理；风扇和外围附件在切平面附近形成片段。`cameras/camera-crank-1280x720.png` 的运动链本身清楚，但仍被未处理的切边围绕。
- **用户可见影响：** 用户能看到内部，却难以区分“被切开的实体材料”与“本来就是空腔”，教学空间关系不够可信。
- **预期收益：高。** 有颜色/纹理的 cut cap 会让剖面从调试式 clipping 提升为工程剖视。
- **实现成本：高。** 通常需要 stencil/多遍渲染、封口几何或近似剖面层。
- **风险：高。** 易引入透明排序、阴影、后处理、draw calls 和多材质维护问题。
- **可验证验收：** 缸体/缸盖/油底壳切面具有一致但可区分的封口材质或剖面纹理；不出现开放空壳和漂浮残片；曲柄连杆四组保持完整可读；性能数据单独复测。

### V3-VIS-08 — 深色附件和核心运动件在前视/低位机位与背景粘连

- **严重度：P2**
- **实际证据：** `cameras/camera-front-1280x720.png` 的风扇、皮带轮区域，`cameras/camera-crank-1280x720.png` 的部分平衡重，以及 `browser/desktop-solid.png` 的油底壳暗部，均与暗背景/地面接近；飞轮和涡轮高光明显，而大面积铸件显得较平。
- **用户可见影响：** 重要结构虽存在，却需要费力辨认；材质之间的金属层级在暗部被压缩。
- **预期收益：中高。** 小幅增加轮廓光、局部补光、接触反差和粗糙度差异即可提升核心件可读性。
- **实现成本：小至中。** 主要是灯光与材质参数调优。
- **风险：中。** 过亮会破坏深色工业风，金属高光可能过曝，透明模式也可能变得发灰。
- **可验证验收：** 六机位的灰度截图中，风扇、前端轮组、油底壳边界和曲轴平衡重仍可与背景分离；飞轮/涡轮不过曝；实体、X-Ray、剖切分别检查材质层级。

### V3-VIS-09 — Draw Calls 偏高且完全没有实例化，低端环境余量有限

- **严重度：P2**
- **实际证据：** `browser/acceptance-report.json`：SwiftShader 平均 12.52 fps，p95 帧时间 91.7 ms，最大 108.3 ms，约 377.04 draw calls/帧；`drawArraysInstanced=0`、`drawElementsInstanced=0`。场景包含大量重复环、弹簧、螺栓、加强筋和粒子网格。
- **用户可见影响：** 本次软件渲染已明显不流畅；不能据此推断普通硬件 GPU 帧率，但 377 次调用意味着集成显卡和高分屏仍可能有压力。
- **预期收益：中高。** 对静态重复件和同材质小件做实例化/合并，可在不降低几何观感的前提下降低 CPU 提交成本。
- **实现成本：中至高。** 需要保留零件拾取、分组显隐、X-Ray/剖切和动画索引。
- **风险：中。** 实例化会复杂化射线拾取、单件高亮与不同透明状态；过度合并会破坏选择粒度。
- **可验证验收：** 同一桌面实体场景下降到不高于 220 draw calls/帧；正式记录硬件 GPU 的型号、分辨率与帧率（目标 1080p ≥45 fps），并把 SwiftShader 单独列示；拾取、模式切换和动画回归通过。

### V3-VIS-10 — 自动验收偏向“状态已切换”，尚不能防止可见质量回归

- **严重度：P2**
- **实际证据：** `browser/acceptance-report.json` 能证明按钮 active、指针变换、选中字段数与无异常，却不能判定顶部机位是否裁切、窄屏模型是否可见、流体 on/off 是否有感知差异或高亮是否贴合。默认 `npm test -- --run` 又拾取了 `artifacts/v3/phase1/mechanics/mechanical-audit.test.ts`，使正式测试从 17 项变成 20 项。证据集中也没有独立爆炸视图截图。
- **用户可见影响：** 视觉问题可能在“全部测试通过”时仍存在；测试数量会随 artifacts 内容变化，降低报告可复现性。
- **预期收益：中。** 收紧发现范围并加入可见包围盒/截图断言，可让后续迭代更可靠。
- **实现成本：小至中。** Vitest include 配置很小；视觉断言和基准管理需要一定维护。
- **风险：低至中。** 像素级比较在不同 GPU 上可能不稳定，应使用布局/包围盒与宽容阈值。
- **可验证验收：** Vitest 只发现 `tests/**/*.test.ts`，即使 artifacts 中存在 `.test.ts` 也保持固定 17 项（或新的明确正式数量）；浏览器测试断言相机稳定后的模型安全边距、核心结构可见面积、流体差异阈值、六机位可达、窄屏画布保留量，并保存独立爆炸截图。

### V3-VIS-11 — 标签在默认与剖切视图仍有局部聚集/语义脱节

- **严重度：P3**
- **实际证据：** `browser/desktop-solid.png` 与 `cameras/camera-isometric-1280x720.png` 中涡轮/排气相关标签和引线集中在同一区域；`browser/desktop-section.png` 中个别标签仍指向被裁去或仅剩片段的外围结构。
- **用户可见影响：** 不阻断操作，但会增加局部视觉噪声，降低剖视图的教学聚焦。
- **预期收益：中低。** 按机位优先级、遮挡和剖切可见性动态筛选可让画面更干净。
- **实现成本：中。** 需要稳定的屏幕空间排布、优先级和时间滞后策略。
- **风险：中。** 自动避碰可能抖动或频繁隐藏标签。
- **可验证验收：** 六机位 1280×720 稳定 2 秒后，主要标签无重叠、引线不交叉核心部件；被剖掉的部件不显示标签；相机轻微移动不产生明显抖动。

## 候选改进排序

按“用户可见收益 ÷ 实现成本”排序，不等同于严重度排序：

1. **修正顶部机位 fit 与安全区（V3-VIS-05）**：小成本、高可见收益、风险最低。
2. **改善暗部轮廓与材质层级（V3-VIS-08）**：小到中成本，可同时提升前视、实体与曲柄机位。
3. **收紧选中高亮并显露检查器滚动/折叠（V3-VIS-06）**：小到中成本，直接去除调试感。
4. **让窄屏改为抽屉/折叠 UI（V3-VIS-01）**：收益很高，但涉及响应式状态与触摸验证。
5. **增强流体路径的方向和层次（V3-VIS-02）**：教学收益很高，需谨慎控制透明排序与 draw calls。
6. **补全前端轮组和皮带传动（V3-VIS-03）**：机械可信度收益高，模块边界也相对清楚。
7. **限制测试发现范围并增加几何/构图断言（V3-VIS-10）**：成本较低，主要收益在后续迭代防回归。
8. **实例化重复小件（V3-VIS-09）**：性能潜力明显，但需保护拾取和模式切换。
9. **丰富缸体/缸盖铸造轮廓（V3-VIS-04）**：视觉上限收益可观，改动面与性能风险较大。
10. **剖切封口/剖面材质（V3-VIS-07）**：观感收益高但技术与性能风险最高，应在前述低成本项之后实施。
11. **标签避碰与剖切感知（V3-VIS-11）**：属于精修，优先级低于结构和视图问题。

## 高收益判断

- **仍存在明显的高收益、低成本问题：是。** 顶部机位重新 fit、暗部补光/材质微调、检查器滚动提示与缩小选择包围框都属于当前就值得做的改进。
- **高收益、中等成本：** 窄屏抽屉式布局、流体路径强化、前端附件皮带传动。
- **不属于低成本快修：** 真正的剖切封口、外壳铸造重塑、全面实例化。它们值得规划，但不能低估与透明、拾取、性能和几何穿插的联动风险。
- **建议下一阶段选择：** 优先实现 05、08、06 三项低成本改进，再从 01、02、03 中选择一到两项边界清楚的模块化修改；不要同时重做壳体、剖切管线与实例化。

## 最终审查意见

当前版本可作为稳定的桌面教学演示继续迭代，但还不应以“视觉与交互质量已无明显高收益空间”收口。若本轮只允许少量改动，至少应修正顶部机位、选择反馈，并在窄屏可用性或流体可读性中完成一项；之后再由未参与实现的代理按相同尺寸复验三模式、六机位和移动视口。
